## 重點（依 lesson）

### §1.3 物件與變數
- 直接寫在原始碼裡的值叫字面值（literal），例如 `5`、`'H'`、`"Hello"`；字面值是唯讀的，不能修改，所以要存資料需要別的機制。
- 字元用單引號，文字用雙引號，數字不加引號；沒加引號的文字會被當成程式碼，幾乎一定編譯失敗。
- 物件（object）是一塊可以存值的記憶體；有名字（識別字）的物件就是變數（variable）。
- 定義敘述（例如 `int x;`）告訴編譯器：要一個這個名字、這個型別的變數。目前先把變數定義在 `main()` 裡面。
- 型別決定物件能存什麼值；型別必須在編譯時就確定，不能改。`int` 變數只能存整數。
- 原站建議：不要在同一個敘述裡定義多個變數，每個變數各寫一行，並加上註解說明用途。

### §1.4 賦值與初始化
- 變數定義好之後，用 `=`（賦值運算子）給它值，叫賦值（assignment）；會把右邊的值複製到左邊的變數。
- 一個變數同時只能存一個值，新的賦值會覆蓋舊值。
- 新手最常見的錯誤之一：把賦值 `=` 和判斷相等的 `==` 搞混。
- 初始化（initialization）是在定義的同時給初始值。口訣：「initial-ization」。
- 寫法：
  - 預設初始化 `int a;`：沒有給值，通常是垃圾值。
  - 複製初始化 `int b = 5;`：從 C 繼承來的寫法。
  - 直接初始化 `int c ( 6 );`。
  - 直接列表初始化 `int d { 7 };`：原站推薦。
  - 值初始化 `int e {};`：通常會變成 0。
- 列表初始化（大括號）不允許縮窄轉換：`int w1 { 4.5 };` 編譯失敗；`int w2 = 4.5;` 會默默丟掉 .5 變成 4。
- `int a, b = 5;` 只有 b 被初始化，a 沒有。
- 原站建議：
  - 優先用大括號初始化。
  - 定義變數時就初始化。

### §1.6 未初始化變數與未定義行為
- C/C++ 不會自動把大多數變數初始化為 0；未初始化的變數裡是記憶體原本的垃圾值。
- 術語區分：
  - 「初始化」：定義時給已知的值。
  - 「賦值」：定義後才給值。
  - 「未初始化」：還沒有被給過已知的值。
- 使用未初始化變數的值，結果無法預測，這是第一個未定義行為（UB）的例子：語言沒有規定會發生什麼事。
- UB 可能的症狀：
  - 每次執行結果不同，或一直給出錯誤的結果。
  - 行為不一致，或看起來正常、之後才出問題。
  - 程式當掉。
  - 只在某些編譯器上正常。
  - 改了無關的程式碼就壞掉。
  - 也可能剛好給出正確結果。
- 大多數現代編譯器會試著偵測未初始化的使用，通常會給警告或錯誤。
- 規則：避免所有會造成未定義行為的情況。

### §1.7 關鍵字與命名
- 關鍵字（例如 `int`、`return`、`if`、`else`、`for`、`while`）保留給 C++ 自己用。
- 識別字規則：
  - 不能是關鍵字。
  - 只能用字母、數字和底線。
  - 必須以字母或底線開頭，不能用數字開頭。
  - 大小寫有別。
- 慣例：
  - 變數名稱以小寫字母開頭。
  - 多個字可以用底線分開（snake_case），或從第二個字起首字母大寫（camelCase）。
  - 避免用底線開頭。
  - 名字要表達用途。
  - 除非是常見又不會混淆的縮寫（如 `num`、`idx`），否則避免縮寫。
