## 重點（依 lesson）

### §0.4 C++ 開發流程
- 先想清楚「要解決什麼」和「怎麼解決」，再寫程式；直接開始寫容易寫出難改、bug 多的程式。
- 你打的指令叫原始碼（source code）；主要的原始碼檔案慣例上命名為 `main.cpp`。
- bug＝任何讓程式無法正確運作的程式錯誤。

### §0.5 編譯器、連結器與函式庫
- 編譯器逐一檢查每個 `.cpp` 是否符合 C++ 規則，有錯就回報行號並中止；沒錯就翻成機器語言，存成目的檔（`.o` / `.obj`）。
- 連結器把目的檔和函式庫組合成執行檔；找不到定義時會出現連結錯誤。
- C++ 標準函式庫中的 iostream 負責印出文字和讀取鍵盤輸入；大多數連結器預設就會連結標準函式庫。
- 把原始碼變成執行檔的整個過程叫「建置」（build）。

### §0.7 編譯第一支程式
- 命令列編譯：`g++ -o HelloWorld HelloWorld.cpp`，執行：`HelloWorld`（或 `./HelloWorld`）。
- 編譯失敗時：讀錯誤訊息、檢查回報的那一行和附近有沒有打錯字。
- 不懂 Hello World 的每一行沒關係，下一章（1.1）會解釋。

### §0.8 常見問題
- 出現「cin、cout 或 endl 是未宣告的識別字」→ 要 `#include <iostream>`，並在每次使用時加上 `std::`。
- 一支程式只能有一個叫 `main` 的函式。

### §1.1 敘述與程式結構
- 敘述（statement）是讓程式執行動作的指令，是最小的獨立計算單位，就像自然語言中的句子。
- 大部分（不是全部）敘述以分號結尾。
- 每支程式都必須有一個叫 `main`（全小寫）的函式；`main` 裡的敘述依序執行，最後一個敘述執行完程式通常就結束。沒有 `main` 會連結失敗。
- Hello World 逐行解釋：`#include <iostream>` 是前置處理器指令，引入後才能用 `std::cout`；`{ }` 標出函式主體；`return 0` 代表程式順利執行。
- 違反語法規則時編譯器會停下來回報語法錯誤；要修正所有語法錯誤才能完成編譯。
- 編譯器有時會把錯誤回報在「應該修正的那一行」的下一行（原站例子：Clang 回報第 5 行，Visual Studio 回報第 6 行）→ 錯誤不在回報的那一行時，就往上一行找。

### §1.2 註解
- `//` 單行註解（到行尾為止）、`/* */` 多行註解；編譯器會忽略註解。
- 多行註解不能巢狀：第一個 `*/` 就結束註解。
- 敘述層級的註解要說明「為什麼」，不要重複程式碼在做什麼。
- 「註解掉」程式碼：把程式碼變成註解，暫時不執行。

### §1.5 iostream：cout、cin、endl
- `std::cout` 把資料送到主控台，`<<` 叫插入運算子；一個敘述裡可以串好幾個 `<<`。
- 分開的輸出敘述**不會**自動換行，要換行必須輸出換行字元。
- `std::endl` 會換行並清空緩衝區（通常沒必要）；原站建議主控台輸出優先用 `'\n'`。`'\n'` 用的是反斜線，寫成 `'/n'` 會出現奇怪的結果（原站說常常印出 12142）。
- 一行輸出完成時，就輸出換行。
- `std::cin` 用 `>>` 讀取鍵盤輸入；讀取失敗（例如在 int 輸入字母）時變數會變成 0。
- 比喻：把 `<<`、`>>` 想成輸送帶，資料往箭頭方向移動。

### §3.1 語法錯誤與語意錯誤
- 語法錯誤：違反 C++ 文法（例如少分號、括號不成對），編譯器會抓到。
- 語意錯誤（邏輯錯誤）：語法正確，但違反其他規則，或沒做到程式設計者想要的事。
- 有些語意錯誤編譯器抓得到；有些要到執行時才出現：可能讓程式當掉，或產生錯誤的結果。
