# 程式骨架

**一句話定義**：一支 C++ 程式是一連串的敘述（statement），從 `main` 函式（function）開始，由上往下一個一個執行 [01 §1.1]。
**先備概念**：無（這是第一頁）

## 白話解釋
敘述就像文章裡的「句子」：每個敘述是一個讓電腦去做某件事的指令，也是程式裡最小的獨立單位 [01 §1.1]。電腦從 `main` 的第一個敘述開始，照順序一句一句做，做完最後一句，程式通常就結束了 [01 §1.1]。

但電腦看不懂你寫的文字。你寫的原始碼（source code）要先交給**編譯器（compiler）**翻譯，再交給**連結器（linker）**組合，才會變成可以執行的程式 [01 §0.4、§0.5]：

| 步驟 | 誰做 | 做什麼 |
|---|---|---|
| 1. 寫原始碼 | 你 | 把指令打進 `.cpp` 檔；主要的檔案慣例命名為 `main.cpp` [01 §0.4] |
| 2. 編譯 | 編譯器 | 檢查每個 `.cpp` 有沒有違反 C++ 規則，有錯就回報行號並停止；沒錯就翻成機器語言（目的檔）[01 §0.5] |
| 3. 連結 | 連結器 | 把目的檔和函式庫組合成執行檔 [01 §0.5] |
| 4. 執行 | 你 | 執行產生出來的程式 [01 §0.7] |

步驟 2＋3 合起來叫做「建置」（build）[01 §0.5]。在命令列上可以這樣編譯和執行 [01 §0.7]：

```text
g++ -o HelloWorld HelloWorld.cpp
./HelloWorld
```

> 本 wiki 的所有範例都統一用 `g++ -std=c++17 -Wall -Wextra -pedantic-errors` 編譯（本 wiki 的規定，見 CLAUDE.md）。

## 語法

### 最小的程式
範例檔：examples/10-hello-world.cpp
```cpp
// 出處：learncpp 1.1（改寫）→ sources/01-learncpp-program-structure.md
#include <iostream>

int main()
{
    std::cout << "Hello world!\n";
    return 0;
}
```
實際輸出：
```text
Hello world!
```

| 程式碼 | 意思 |
|---|---|
| `// 出處：…` | 註解，編譯器會忽略（見下方「註解」）[01 §1.2] |
| `#include <iostream>` | 前置處理器指令：引入 iostream，才能使用 `std::cout` [01 §1.1] |
| `int main()` | 定義 `main` 函式。每支程式都必須有一個 `main`（全小寫），沒有的話會連結失敗 [01 §1.1]；而且只能有一個 [01 §0.8] |
| `{` 和 `}` | 標出函式主體的開始和結束 [01 §1.1] |
| `std::cout << "Hello world!\n";` | 第一個敘述：把文字印到螢幕上 [01 §1.1] |
| `return 0;` | 告訴系統程式順利執行，是最後一個執行的敘述 [01 §1.1] |

大部分（不是全部）敘述以分號 `;` 結尾 [01 §1.1]。

### 輸出：`std::cout`
- `std::cout` 把資料送到螢幕（主控台），`<<` 叫插入運算子（insertion operator）[01 §1.5]。
- 可以把 `<<` 想成一條**輸送帶**：資料沿著箭頭方向，被送進 `std::cout` [01 §1.5]。
- 一個敘述裡可以串好幾個 `<<`，把好幾段內容接在一起印 [01 §1.5]。
- **分開寫的輸出敘述不會自動換行**，要換行必須自己輸出換行字元 `'\n'`；它也可以直接寫在雙引號文字裡面，例如 `"Hello\n"` [01 §1.5]。
- 一行輸出完成時，就輸出換行 [01 §1.5]。

範例檔：examples/11-cout-chain.cpp
```cpp
// 出處：learncpp 1.5（改寫）→ sources/01-learncpp-program-structure.md
#include <iostream>

int main()
{
    std::cout << "Hi!" << '\n';                 // 用 << 串接：先印文字，再印換行
    std::cout << "My name is " << "Alex." << '\n';
    return 0;
}
```
實際輸出：
```text
Hi!
My name is Alex.
```

> ⚔️ 衝突：換行也可以寫 `std::endl`，但它除了換行還會清空緩衝區，原站說這通常沒必要，建議主控台輸出優先用 `'\n'` [01 §1.5]。本 wiki 一律用 `'\n'`。

> 輸入（`std::cin`）需要先學會「變數」，放在下一頁：[變數與型別](variables-and-types.md)。

### 註解
- `//` 是單行註解：從 `//` 到這一行結尾都會被編譯器忽略 [01 §1.2]。
- `/* … */` 是多行註解：中間的內容都會被忽略，但**不能巢狀**，第一個 `*/` 就會結束註解 [01 §1.2]。
- 在敘述旁邊寫註解時，要說明「**為什麼**這樣寫」，而不是重複程式碼在做什麼 [01 §1.2]。
- 把程式碼變成註解，暫時不讓它執行，叫做「註解掉」（comment out）[01 §1.2]。

範例檔：examples/12-comments.cpp
```cpp
// 出處：自編示意例（語法依據 sources/01-learncpp-program-structure.md §1.2）
#include <iostream>

int main()
{
    // 單行註解：從 // 到這行結尾都會被編譯器忽略
    std::cout << "Hello\n"; // 註解也可以放在程式碼右邊
    /* 多行註解：
       可以跨好幾行 */
    // std::cout << "Bye\n";   ← 被「註解掉」的程式碼，不會執行
    return 0;
}
```
實際輸出：
```text
Hello
```

## 兩種錯誤：語法錯誤 vs 語意錯誤
| | 語法錯誤（syntax error） | 語意錯誤（semantic error） |
|---|---|---|
| 是什麼 | 違反 C++ 文法，例如少分號、括號不成對 [01 §3.1] | 語法正確，但程式沒做到你想要的事 [01 §3.1] |
| 誰會發現 | 編譯器，會停下來回報錯誤 [01 §1.1] | 有些編譯器抓得到；有些要到執行時才會出現：程式當掉，或結果錯誤 [01 §3.1] |
| 怎麼辦 | 修正後重新編譯，直到沒有錯誤 [01 §3.1] | 用不同的輸入測試程式，再除錯（debug）[01 §0.5] |

**語法錯誤的例子**：漏了分號。這段程式碼無法編譯，g++ 的真實錯誤訊息請見[新手常見錯誤 #1](common-mistakes.md#1-漏了分號)。

**語意錯誤的例子**：程式能編譯、也能執行，但結果不是你想要的。

範例檔：examples/13-semantic-error.cpp
```cpp
// 出處：自編示意例（語法依據 sources/01-learncpp-program-structure.md §3.1、§1.5）
#include <iostream>

int main()
{
    // 本來想印成兩行，卻忘了在第一行後面換行
    std::cout << "Hi!";
    std::cout << "My name is Alex.\n";
    return 0;
}
```
實際輸出：
```text
Hi!My name is Alex.
```

## 常見誤解
- ❌「分兩個 `std::cout` 敘述寫，就會印成兩行」→ 不會，必須自己輸出 `'\n'` [01 §1.5]（見 `13-semantic-error.cpp`）。
- ❌「能編譯就代表程式是對的」→ 語意錯誤的程式照樣能編譯和執行，只是結果不對 [01 §3.1]。
- ❌「錯誤一定在編譯器說的那一行」→ 編譯器有時會把錯誤回報在下一行，找不到就往上一行看 [01 §1.1]。
  > ⚔️ 衝突：原站的例子是 Visual Studio 把漏分號回報在下一行 [01 §1.1]；本機 g++ 15.2 實測則回報在**漏分號的那一行**，只在訊息裡說 `before 'return'`，並把下一行一起顯示（見[常見錯誤 #1](common-mistakes.md#1-漏了分號)）。結論：不同編譯器行為不同，「往上一行找」這個習慣仍然有用。
- 更多錯誤寫法見 [新手常見錯誤](common-mistakes.md)。
